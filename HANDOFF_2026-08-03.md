## 2. What changed — by theme

### Auth & session reliability

| File | Change |
|---|---|
| `src/lib/authLock.js` **(new)** | The auth lock, extracted and **fixed** |
| `src/lib/__tests__/authLock.test.js` **(new)** | 8 tests pinning the auth-js contract |
| `src/lib/supabase.js` | Uses the extracted lock; exports `purgePersistedAuthToken` |
| `src/main.jsx` | `visibilitychange` → `startAutoRefresh()` |
| `src/lib/durableStorage.js` | New `clearDurable()` |
| `src/contexts/AuthContext.jsx` | signOut / deleteAccount now await `clearDurable()` |
| `src/lib/__tests__/durableStorage.test.js` **(new)** | 5 tests, mocked Capacitor |

**The lock bug:** `inMemoryLock` accepted `acquireTimeout` and ignored it. `getSession()`
runs on **every** Supabase REST request, so one hung holder wedged the entire app until
relaunch — exactly the "session goes stale and never reloads" symptom. Proven by running
the new contract tests against a verbatim copy of the old implementation: **4 of 8 hung**
until vitest killed them at 5s.

**The logout bug (native, cold start only):** `clearPersistedUserData` wiped localStorage
and nothing else. On native those same keys are mirrored into `@capacitor/preferences`,
which survives an app kill **and an overwrite install**, and `hydrateFromDurable()` copies
them back *before React mounts*. The previous member's account painted itself back on —
token-less, so every request went out as `anon`. Second hole found alongside it: signOut's
last-resort fallback swept **localStorage** for `sb-*-auth-token`, the one place the native
adapter never writes it.

### Admin "Add Member" / invites

`src/pages/admin/components/CreateInviteModal.jsx` (+230), `send-admin-email`,
`send-invite`, `src/lib/referralCode.js` **(new)**, migrations 0678 + 0679.

Four separate root causes, all traced before touching anything:

1. **Referral codes have been untypeable since mig 0653.** `generate_referral_code` went
   4 → **8 hex**, making a code `REF-XXXX-XXXXXXXX` = **15 alphanumerics**. Both
   formatters (Signup + Onboarding, copy-pasted) capped at `.slice(0, 11)`. Every code
   minted since was truncated *as you typed it* and came back "invalid" — only the QR
   worked. Now one shared helper + 7 tests, wired into Signup, Onboarding, and the invite
   modal.
2. **The referral on an invite was write-only.** The modal stored
   `gym_invites.referral_code_id` and *nothing ever read it back*. The referral is
   registered client-side by `register_referral(p_code, …)`, which takes the code TEXT —
   never handed over. Invites carried name/email/phone perfectly and silently dropped the
   referral.
3. **"Member has no email on file."** `admin_create_member` deliberately mints a SHADOW
   auth user at `invite-<uuid>@invite.tugympr.invalid`; the real address lives on
   `auth.users.raw_user_meta_data.pending_email` and `gym_invites.email`. Mig 0603 taught
   the *display* RPCs that rule; `send-admin-email` never learned it. It also **discarded
   the getUserById error**, so every failure wore that one misleading message.
4. **The prefill needed BOTH surfaces.** An invite link lands on **Signup**
   (`/invite/:code`), not Onboarding. Both are wired now.

Also: live email-taken check (debounced 450ms, fails **open** if the RPC is missing);
delivery unified on `send-invite` with per-channel failure reasons surfaced on the result
screen; the share sheet now embeds the URL in the text so a copy-paste carries the link.

## 3. Durable gotchas worth keeping

- **auth-js lock contract:** `acquireTimeout < 0` = wait forever; `= 0` = throw NOW if busy;
  `> 0` = throw after that long. The error must carry `isAcquireTimeout === true` — checked
  **by property, not `instanceof`**. `_autoRefreshTokenTick` passes `0`.
- **`stopAutoRefresh()` calls `_removeVisibilityChangedCallback()`** — permanently removing
  auth-js's own visibility handling after the first background. That's why `main.jsx` has to
  restart it by hand.
- **Store links live in TWO places** and both must be set: `src/lib/appUrls.js` (compile-time,
  for `/get` and member shares) and `app_config` (for email footers — an edge function can't
  import from `src/`).
- **Drop `&pcampaignid=web_share`** from the Play link. It attributes the install to "tapped
  share inside the Play app", which is never where our links come from.
- **`supabase functions list` must run from `gym-app/`** or it errors "Cannot find project ref".
- **Middleware serves OG cards to bots only** (`BOT_UA` includes `facebookexternalhit`) and
  passes through when `getPreview` returns nothing. Verify with:
  ```bash
  curl -A facebookexternalhit https://app.tugympr.com/invite/CODE
  ```
- **Accented SMS bills at 70 chars/segment** (UCS-2), not 160. Never repeat the gym name in
  the body — `smsBody` already opens with it.
- **Vercel's root is the repo root** (`vercel.json` does `cd gym-app && …`), so the root
  `middleware.js` IS deployed.
